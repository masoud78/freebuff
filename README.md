# Freebuff

اپلیکیشن **Local-first** برای تبدیل تماس‌ها و ویس‌های فروش سفر به متن، استخراج نکات کاربردی و ساخت یک دیتابیس دانش برای مقصدهای سفر — با استفاده از Gemini و بدون ارسال داده به هیچ سرویس دیگری.

تمام پردازش‌ها روی سیستم خودتان اجرا می‌شوند؛ کلید Gemini و دیتابیس به‌صورت محلی نگهداری می‌شوند.

## امکانات

- **تبدیل ویس به متن فارسی** با تشخیص گوینده (فروشنده/مشتری)، رعایت املای فارسی و یک مرحلهٔ تصحیح خودکار در پس‌زمینه.
- **استخراج نکات و دغدغه‌های مشتری** از مکالمه، با تشخیص نکات تکراری (هم‌موضوع با ظاهر متفاوت) و بدون تولید اطلاعات بی‌مبنا.
- **دیتابیس مقاصد** با نسخه‌بندی نکات، لاگ تغییرات و پیوند به ویس منبع هر نکته.
- **خبرهای پردازش** به‌صورت بخش‌های آمادهٔ انتشار (عنوان H2 و در صورت نیاز H3)؛ وقتی اطلاعات جدیدی نباشد، دلیل آن صادقانه نوشته می‌شود، نه خبر ساختگی.
- **انتخاب مدل و بررسی سهمیه** — فقط مدل‌های دارای قابلیت صوت برای تبدیل ویس به متن نمایش داده می‌شوند و وضعیت سهمیهٔ هر مدل قبل از انتخاب مشخص است.
- **پشتیبانی از پروکسی سیستم** — اگر روی ویندوز پروکسی تنظیم شده باشد، همهٔ درخواست‌های Gemini از همان پروکسی عبور می‌کنند (برای کاربران مناطق محدودشده).

## چرخهٔ کار

```text
۱. آپلود ویس  →  ۲. تبدیل به متن  →  ۳. پردازش و استخراج نکات  →  ۴. اعمال در دیتابیس  →  ۵. خبرهای پردازش
```

هر مرحله فقط با اقدام صریح کاربر جلو می‌رود و در دیتابیس ذخیره می‌شود؛ بعد از Restart هیچ کاری گم نمی‌شود.

## پشتهٔ فناوری

| لایه | تکنولوژی |
| --- | --- |
| رابط کاربری | React + Vite + Tailwind CSS (فارسی و RTL) |
| سرور | Fastify + pino + Zod |
| دیتابیس | SQLite + Drizzle ORM (Migration خودکار در Startup) |
| قراردادهای مشترک | `packages/contracts` — اسکیمای Zod و تایپ‌های API |
| هوش مصنوعی | Gemini (`@google/genai`) |
| ابزارها | pnpm workspace · TypeScript strict · node:test |

## پیش‌نیازها

- Node.js نسخهٔ **۲۴** یا بالاتر
- pnpm نسخهٔ **۱۱** (نسخهٔ دقیق در فیلد `packageManager` ریشه مشخص شده است)

## نصب و اجرا

```bash
pnpm install
pnpm dev
```

بعد از اجرا:

- **Web:** http://localhost:5173
- **API:** http://localhost:8787/api/health

در حالت توسعه، Vite درخواست‌های `/api` را به سرور Fastify پراکسی می‌کند؛ بنابراین مرورگر درخواست cross-origin ندارد.

## اسکریپت‌ها

| اسکریپت | توضیح |
| --- | --- |
| `pnpm dev` | اجرای هم‌زمان Web و Server با بارگذاری مجدد خودکار |
| `pnpm build` | ساخت نسخهٔ تولید (web: Vite، server: tsc + کپی Migrationها) |
| `pnpm typecheck` | بررسی تایپ کل workspace با `tsc` |
| `pnpm lint` | اجرای ESLint روی کل پروژه |
| `pnpm test` | اجرای تست‌های سرور (node:test با Gateway Mock — بدون دسترسی به API واقعی) |
| `pnpm db:generate` | تولید Migration جدید از Schema (Drizzle Kit) |
| `pnpm db:migrate` | اجرای Migrationهای در انتظار |
| `pnpm db:studio` | باز کردن Drizzle Studio |

## ساختار مخزن

```text
/
├── apps/
│   ├── web/          # رابط کاربری فارسی و RTL
│   └── server/       # API، صف Job و منطق پردازش
├── packages/
│   └── contracts/    # اسکیمای مشترک Zod و تایپ‌های API
├── workspace/        # داده‌های محلی (database و secrets — خارج از Git)
├── docs/             # مستندات معماری و عملیات
├── package.json
└── pnpm-workspace.yaml
```

## داده و امنیت

- **دیتابیس:** فایل SQLite در `workspace/system/database/app.db`؛ Migrationها هنگام Startup خودکار اجرا می‌شوند.
- **کلید Gemini:** در `workspace/system/secrets/gemini.key` ذخیره می‌شود و هرگز در پاسخ‌های API یا لاگ‌ها ظاهر نمی‌شود.
- **پروکسی:** ابتدا متغیرهای استاندارد (`HTTPS_PROXY`/`HTTP_PROXY`) و سپس پروکسی سیستم ویندوز خوانده می‌شود؛ با `FREEBUFF_NO_PROXY=1` می‌توان آن را غیرفعال کرد.

## قراردادهای توسعه

- TypeScript در حالت `strict` در کل workspace.
- اسکیمای مشترک و تایپ‌های API فقط در `packages/contracts` تعریف می‌شوند.
- منطق Business داخل کامپوننت‌های React نوشته نمی‌شود.
- خروجی هوش مصنوعی همیشه قبل از نوشتن در دیتابیس با Zod اعتبارسنجی می‌شود.
